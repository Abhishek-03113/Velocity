# Velocity v1.0

**Release date:** August 8, 2026

The first stable release of Velocity — a self-hosted, local-first **notes manager** built around one principle: *the UI never waits for the server.*

---

## Highlights

- **Instant editing** — all interactions resolve in Zustand state; SQLite persistence is async and debounced
- **Markdown-native editor** — CodeMirror 6 with live preview, read mode, and rich formatting shortcuts
- **Per-note whiteboard** — Excalidraw canvas in a resizable split pane
- **Sub-10 ms search** — FlexSearch index over titles and content, persisted in `localStorage`
- **Docker-ready** — one-command deploy via `make up`

---

## New in v1.0

### Notes & Organization

- Browser-style tab bar with inline rename, close-without-delete, and unsynced indicator
- Sidebar note list with group filtering and drag-and-drop group assignment
- Flat group/folder model — create, rename, delete; deleting a group unassigns notes
- Up to 5 MRU unnamed notes in sidebar; named notes always preserved
- Lazy content loading — note body fetched on first tab open

### Editor

- CodeMirror 6 with Markdown syntax highlighting (Catppuccin theme)
- Obsidian-style live preview — headings, emphasis, code, links, task checkboxes
- Read mode toggle (`⌘/Ctrl + E`) — full rendered preview via `marked`
- Multi-cursor editing (`Alt + Click`)
- Formatting shortcuts: bold, italic, inline code, strikethrough, links
- Image paste, drag-and-drop, and clipboard insert with server-side asset storage
- Status bar: word count, line count, group name, save state

### Whiteboard

- Per-note Excalidraw drawing board (`⌘/Ctrl + Shift + D`)
- Resizable split pane alongside the editor
- Scene data persisted per note in `localStorage`

### Search

- Client-side FlexSearch index (title + content)
- Index serialized to `localStorage` on each write, hydrated on startup
- Inline editor search (`⌘/Ctrl + F`)
- Global search modal across all notes (`⌘/Ctrl + Shift + F`)

### Sync & Backend

- Debounced writes (~800 ms idle) to SQLite via Hono REST API
- Dirty-state tracking with retry queue (exponential backoff, max 3 attempts)
- Server-side write failure logging
- Image asset API with deduplication (`/api/assets`)
- Docker Compose stack: client (nginx), server, API proxy
- Makefile targets: `up`, `down`, `restart`, `rebuild`

### UI

- Dark theme with Tailwind CSS 4
- Collapsible sidebar (`⌘/Ctrl + 1`) with animation
- In-app keyboard shortcuts reference modal
- Responsive layout

## Getting Started

```bash
git clone <repo-url> velocity && cd velocity
cp .env.example .env
make up
# → http://localhost:37801
```

For local development:

```bash
npm run install:all && npm run dev
# → http://localhost:5173
```

---

## Known Limitations

- No authentication — for trusted local / self-hosted use only
- No collaboration or real-time sync
- No export / import
- Whiteboard data is browser-local, not synced to SQLite
- 1 MB per-note soft cap warning not yet shown in the UI
- No automated test suite

---

## Out of Scope (by design)

Authentication, collaboration, theming, real-time sync, export/import, IndexedDB, and user-facing error toasts are intentionally deferred.

---

## Philosophy

> "Backend stores. Frontend thinks."

> "If the UI waits, the system is broken."

> "Resilience is silent. The indicator shows; the queue handles it."
